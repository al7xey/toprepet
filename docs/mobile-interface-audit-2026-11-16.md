Осмотр этих экранов не означает проверку каждой комбинации данных. Публикация анкет, удаления и отправка жалоб не выполнялись вручную на данных пользователя. Полные мастера регистрации и заявки, бронирование и изменение расписания дополнительно проверяются изолированными сквозными тестами.

## Единые правила интерфейса

- Белый фон и яркий оранжевый акцент. Существующая система размеров, круглая навигация и белые стеклянные действия сохраняются.
- Button, IconButton, PageHeader, Person, LoadingList, ErrorState используются повторно. Иконки получают доступные подписи, ошибки не маскируются пустыми состояниями.
- Крупные модальные поверхности плотнее небольших стеклянных кнопок: фон не должен мешать чтению и заполнению формы.
- Пароль не разряжается, код допускает вставку и автозаполнение `one-time-code`. Клавиатура не открывается автоматически при переходе к форме.
- Демо-подтверждение честно показывает отдельный демонстрационный код. Оно не выдаётся за отправку настоящего письма.

## Анимации и дальнейшие улучшения

Сохраняются существующие плавный индикатор нижнего меню и последовательное появление шагов при прокрутке. Заголовки и поля ввода остаются неподвижными. Движение учитывает `prefers-reduced-motion`.

Для дальнейшей настройки подходят появление шагов сверху вниз с интервалом 60–90 мс и длительностью 400–500 мс, раскрытие FAQ за 220–280 мс, мягкое перемещение индикатора вкладки за 300–340 мс. Не нужны лупа, масштабирование кнопок, вспышки цвета при нажатии или параллакс фотографии анкеты. Эти значения — предложения для отдельной визуальной настройки, а не заявление о реализации новых эффектов во всех блоках.

## Ограничения окружения

Локально подключён настоящий Django, но почта по умолчанию выводится в журнал сервера. Чтобы письмо реально приходило во входящие, необходимы `EMAIL_URL` и адрес отправителя. Формирование, проверка и одноразовость кода проверены на настоящем локальном HTTP API. Доставка в почтовый ящик не проверена без SMTP.

Vercel-превью использует демо-данные в браузере. В нём код `123456` показан явно; настоящая почта не отправляется. В блоге нет опубликованных статей, а часть демо-документов не содержит файлов: содержимое статьи и просмотр таких файлов невозможно оценить по этому набору данных. Физическая клавиатура iOS и доставка писем требуют отдельной проверки на устройстве и подключённом почтовом сервисе.

## Дополнительная доводка после проверки 320 / 390 / 1440 px

- На 320 px имя в карточке с рейтингом больше не разрывается посередине слова: отступы плашки адаптируются к узкой сетке.
- На компьютере убрана дублирующая кнопка возврата поверх фотографии; основная навигация остаётся над анкетой.
- Мобильное модальное окно получает фокус без автоматического перехода в поле ввода. Поля, ссылки и кнопки исключены из жеста закрытия шторки; отмена касания возвращает её на место.
- При ошибке отметки уведомления прочитанным восстанавливается непрочитанное состояние и показывается сообщение об ошибке. Убран лишний запрос списка уведомлений из профиля ученика.
- Поле кода подтверждения принимает вставку с пробелом, например `123 456`, без потери последней цифры; автокоррекция выключена.

Проверки жестов и переноса имени добавлены в `e2e/polish.spec.ts`. Физическое поведение клавиатуры iOS остаётся отдельной проверкой на устройстве.
