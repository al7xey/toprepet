# Исправления по аудиту design/home-mockup

Работа включает исправления аудита от 05.11.2026 и дополнительные регрессионные проверки. Активный UI расположен в `src/new-design/ui`; неиспользуемый `components/ui` удалён вместе с зависимостями.

## Исправлено

- Слоты учитывают минуты, полную длительность, пересечения, рабочие границы и несуществующее локальное время при переходе DST. Пересекающиеся интервалы сервера объединяются.
- Создание и перенос записи используют блокировку репетитора. Повторы брони сериализуются по ученику, проверяют отпечаток запроса и защищены уникальностью непустого ключа. HTTP-клиент отправляет ключ, форма сохраняет его для повторов.
- Цена отклика фиксируется независимо от новой цены анкеты. Обе суммы сохраняются на сервере; внутреннюю цену репетитора ученик не получает.
- Возвраты не увеличивают ожидаемый доход. История платежа сохраняет выбранную карту после её удаления.
- Worker перечитывает урок под блокировкой перед выплатой; автозавершение не перезаписывает спор. Решения споров и ответы блокируются в порядке «урок → спор».
- Email-токен потребляется условным UPDATE; смена пароля и потребление находятся в одной транзакции.
- Значения approve/accept/block валидируются BooleanField. Проверка Origin учитывает scheme/host/port; middleware не читает весь multipart в память. Idempotency-Key разрешён в CORS.
- Каталог фильтруется, сортируется и ограничивается в SQL. Exists для документов и joins review/dispute устраняют повторные запросы; счётчики откликов аннотированы.
- Изменение содержимого опубликованной анкеты возвращает её на проверку. В этой версии анкета скрывается до решения; одновременное хранение одобренной и черновой ревизии остаётся отдельным развитием продукта.
- Фото ограничены по байтам/пикселям, уменьшаются до 1600 px и перекодируются без EXIF.
- Общий sanitizer очищает HTML редактора, снимка блога и публичного вывода. Синхронизация имеет timeout и атомарную замену файла.
- Модальные окна блокируют фон через inert, удерживают Tab/Shift+Tab и возвращают фокус. Ошибки запросов видны; старый профиль не скрывает серверный 404; состояния сбрасываются между репетиторами.
- Все отзывы разворачиваются на странице вместо перехода на несуществующий маршрут.
- Добавлены HTTP timeout, синхронная защита повторных мутаций, пауза chat polling в скрытой вкладке. Убрано двойное сжатие фото.
- Удалены неиспользуемые UI, RSC/Vinext/Cloudflare/Drizzle/Sites-зависимости, обновлены Vite/oxfmt/oxlint, закреплён исправленный source-map-js. Рабочий TipTap/Supabase редактор сохранён.
- Oxlint сохраняет проверки hooks; эвристики React Compiler purity/immutability выключены: проект не использует React Compiler, а эти правила отмечают корректные локальные переменные эффектов.
- Публикация Pages зависит от Quality и Backend reusable workflows, затем проверяет именно публикуемый dist. Публикационная ветка остаётся main.
- Прямые Python requirements закреплены. Без DEBUG=1 Django требует SECRET_KEY; fake payments не включаются по умолчанию вне разработки. Frontend требует явного выбора demo/API; demo предупреждает об отсутствии настоящих операций.

## Миграции

Перед запуском API выполнить `python manage.py migrate`. Для старых откликов цена репетитора восстанавливается обратным округлением действовавшей комиссии 10%. Непустой ключ брони должен быть уникален для ученика. Исторические дубликаты не очищаются автоматически: они требуют ручного решения до миграции.

Локальные команды Django запускать с `DEBUG=1`. Действующие базы, секреты, провайдеры и опубликованный сайт этой работой не изменяются.

## Проверки

- `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm exec tsc --noEmit`, `pnpm test`
- `VITE_API_MODE=demo pnpm build`, `pnpm e2e`
- Из backend: `python -m pytest`, `DEBUG=1 python manage.py makemigrations --check --dry-run`
- `bash backend/scripts/contract.sh`, `bash backend/scripts/e2e.sh`
- `pnpm audit --json`

Добавлены регрессии длинных уроков, минут расписания, пересечений, повторов брони и разных payload, согласованной цены, retry header, булевых полей, Origin, числа SQL-запросов, EXIF, HTML-инъекций и клавиатурного поведения модального окна. Конкурентный тест двух соединений работает на PostgreSQL в Backend CI; на SQLite он явно пропускается.

## Что ещё требуется для настоящего сервиса

Нужны выбранный платёжный провайдер и договорная схема маркетплейса, hosted fields вместо собственного ввода PAN/CVC, журнал внешних операций с уникальными ключами, подписанные webhooks, сверка и retry после сбоя процесса. Транзакция БД не откатывает внешние деньги. Текущий провайдер fake предназначен для разработки; неподключённые провайдеры отвечают 503.

Отдельно нужны Яндекс ID и видеокомнаты, проверенные Supabase RLS/Storage policies (схемы нет в этом репозитории), приватная выдача документов и процесс проверки, курсорная пагинация больших переписок/историй, мониторинг и проверка восстановления копий. Для переписок сохранён совместимый массив API; пауза polling снижает фоновую нагрузку, но не заменяет пагинацию.

Нужны нагрузочные замеры и свежие полевые LCP/INP/CLS. Успех unit/e2e не доказывает отсутствия всех ошибок и не заменяет проверку настоящих провайдеров и инфраструктуры.

## Результаты локальной проверки

136 серверных тестов прошли; один тест PostgreSQL row locking пропущен на локальной SQLite и включён в Backend CI. Vitest: 25 успешных, 14 HTTP-сценариев включаются отдельно и прошли против Django. Сценарий настоящего API в Chromium прошёл. pnpm audit и pip-audit для закреплённых production requirements не нашли известных уязвимостей на дату проверки. Django deploy check: ошибок нет, два осознанно не включённых HSTS subdomains/preload предупреждения; их нельзя включать без проверки доменов.

Полный браузерный прогон: 76 passed, 14 ожидаемых пропусков по размеру экрана и отдельному режиму реального API. Включены новые сценарии клавиатуры модального окна и предупреждения demo на обоих экранах.
