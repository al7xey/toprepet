# Повторный общий аудит TopRepet

Дата: 06.11.2026. Ветка: design/home-mockup. Проверены код, сборка и изолированные тестовые среды. Цель — исправить воспроизводимые ошибки логики и интерфейса, сохранив существующие компоненты, Manrope, цвета, кнопки и плоские поверхности.

## Найдено и исправлено

| Область | Проблема | Решение |
|---|---|---|
| Планшетная навигация | На 768 px меню репетитора накладывалось на логотип и значки. Проверка одной горизонтальной прокрутки этого не обнаруживала. | На 761–1200 px шапка кабинета раскладывается в два ряда; ссылки могут переноситься. Мобильная панель и широкая desktop-шапка сохраняют свой вид. |
| Обновление данных | QueryView скрывал ошибку повторного запроса, если ранее уже получил данные. Даже пустая старая очередь могла отображаться как проверенная при сбое API. | Ошибка и кнопка повтора видны при сохранённых данных; старое пустое состояние не выдаётся за свежий результат. |
| Статусы документов | Карточка копировала входной документ в локальный state и игнорировала новые props после обновления очереди. | Документ отображается из данных родительского запроса; результат модерации обновляет тот же источник данных. Добавлено обновление очереди анкет. |
| Подтверждение удаления | Ошибка удаления карты/сообщения оказывалась под открытым диалогом и недоступным фоном. | Общий ConfirmDialog показывает ошибку внутри окна; новая попытка для другого объекта очищает старую ошибку. |
| Управление документами | После 20 документов отсутствовал способ освободить квоту, в том числе после отказа в проверке. | DELETE /tutor/documents/:id, только для владельца, с подтверждением и понятной ошибкой в UI. Удаление последнего одобренного документа снимает отметку проверки. |
| Очистка файлов | Удаление строки и файла не может быть одной транзакцией PostgreSQL. Сбой файлового хранилища не должен терять задачу очистки. | Задача DocumentFileDeletion создаётся в транзакции удаления документа. Очистка запускается после commit; при сбое задача сохраняется для run_jobs. Общие legacy-пути не удаляются, пока ими пользуется другой документ. Каждое удаление имеет собственную задачу. |
| Запросы документов | Проверки общих путей и поиск pending-документов должны оставаться быстрыми при росте таблицы. | Индекс file, частичный индекс очереди checking; административный запрос получает только используемые поля. |
| Документация API | Во frontend README был указан /v1, которого нет в текущем Django URLconf, и устаревшее автоматическое включение мока. | Указан корректный API base; demo выбирается явно через VITE_API_MODE=demo. |

## Дизайн и UX

Визуально просмотрены каталог и кабинеты; выполнены 63 просмотра маршрутов при ширинах 320, 768 и 1024 px. Внешней горизонтальной прокрутки не обнаружено, но визуальная проверка выявила внутреннее наложение планшетной шапки. Оно воспроизведено и исправлено.

Регрессионные проверки теперь проверяют не только scrollWidth, но и пересечение меню с логотипом/значками, а также фактическую доступность каждой ссылки через elementFromPoint. Проверены desktop и touch-контексты. Внешний вид новых страниц, длинные названия, состояния загрузки, пустой результат, ошибка обновления и повтор запроса проверяются через существующий UI kit.

Применены установленные Frontend Design, Web Design Guidelines, React Best Practices и API Design Principles. Новые визуальные темы и библиотеки не вводились.

## Обновление сервера

В этой версии нужна новая миграция tutors/0003_document_file_cleanup.py. После резервного копирования выполнить python manage.py migrate до запуска обновлённых API/worker. Для больших рабочих таблиц следовать инструкциям по миграционному пользователю и таймаутам из backend-security.md.

Запускать python manage.py run_jobs раз в минуту. Он повторяет до 100 задач очистки за запуск. Ошибки хранилища журналируются с ID задачи и классом ошибки. При отсутствии worker успешные немедленные удаления продолжают работать, но повторные попытки откладываются; heartbeat и ошибки задания нужно мониторить.

## Границы заключения

Проверка не доказывает отсутствия всех ошибок и не является независимым pentest или нагрузочным тестированием production. Действующие SMTP, ingress, резервные копии и Supabase RLS этой работой не проверялись. Настоящие платежи, OAuth и персональные видеокомнаты по-прежнему требуют отдельных интеграций.

Сохранён ранее утверждённый оранжевый цвет. Проверки axe исключают активную ссылку основной шапки по существующему решению владельца; это не заявление о полной сертификации WCAG AA всех цветовых сочетаний. Реальные показатели LCP/INP/CLS и субъективная оценка дизайна требуют проверки на целевых устройствах и пользователях.
