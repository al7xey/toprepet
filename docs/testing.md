# Тестирование

| Что | Команда | Что проверяет |
|---|---|---|
| Типы | `pnpm exec tsc --noEmit` | весь `src`, `e2e`, конфиги |
| Линтер | `pnpm lint` | oxlint |
| Модульные | `pnpm test` | правила мока и общие сценарии `api/scenarios.ts` |
| Бэкенд | `cd backend && python -m pytest` | модели, права по ролям, платежи-заглушка, задачи |
| Контракт | `bash backend/scripts/contract.sh` | те же сценарии, что на моке, против настоящего Django |
| SEO и Метрика | `node scripts/verify-seo.mjs`, `node scripts/verify-analytics.mjs` | после `pnpm build:e2e` |
| Браузер, мок | `pnpm build:e2e && pnpm e2e` | сценарии ниже на 1440 и 390 px |
| Браузер, Django | `bash backend/scripts/e2e.sh` | вход → запись → подтверждение → админка на настоящем сервере |

Сквозные сценарии (`e2e/`):
- `guest` — шапка, каталог → анкета → вход → возврат к записи, старые адреса, 404, документы без убранных формулировок;
- `student` — запись с оплатой картой и отмена, чат с запретом контактов, сброс пароля, отзыв и обращение о проблеме;
- `tutor` — регистрация репетитора → анкета → проверка админом → появление в каталоге; спор от ответа до решения; публикация отзыва;
- `requests` — заявка → отклик → запись по отклику;
- `quality` — axe (WCAG A и AA) без нарушений на всех страницах гостя и трёх кабинетов, нет горизонтальной прокрутки, заголовки 40/30 и 30/26, цели нажатия на телефоне, обход внутренних ссылок без 404;
- `real-backend` — один сценарий на Django (нужен `E2E_API_URL`, запускается скриптом).

Заметки:
- блоки страниц плавно проявляются, поэтому проверки доступности ждут около секунды, иначе axe видит полупрозрачный текст;
- при падении Playwright сохраняет снимок и trace в `test-results/`; в CI они выкладываются артефактом.
