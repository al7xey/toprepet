Находки без доказательств не принимаются; домыслы помечай «гипотеза».

Измерения:
1. Соответствие требованиям владельца. Для каждого сценария: пройден/не пройден, где упал, скриншот. Отдельно: что не реализовано вовсе (маршруты из макетов без страницы, кнопки без действия, ссылки в никуда).

5. Код фронтенда. Архитектура src/new-design: границы модулей, типизация (any, as, неиспользуемые типы), обработка ошибок и состояний загрузки, утечки в эффектах, гонки запросов, мемоизация, повторы, мёртвый код, размер компонентов, соглашения об именах, совместимость с React 19 и SSR/пререндером, соблюдение правил из src/new-design/README.md.
6. Готовность к бэкенду. Сверь api/contract.ts и api/types.ts с реально используемыми вызовами, с макетами и с правилами продукта: чего не хватает (методы, поля, статусы, коды ошибок), где мок ведёт себя не как должен вести себя сервер (деньги, слоты, часовые пояса, права доступа, идемпотентность), как будет переключение на http-клиент (VITE_API_URL, cookie-сессия, CORS, CSRF), какие правила нужно продублировать на сервере. Сравни с существующим MVP на Supabase (feature/new-service, mvp/*): что можно переиспользовать, что конфликтует; предложи решение (оставить Supabase, мигрировать на Django по docs/architecture-plan.md, или гибрид) с плюсами, минусами и сроками.
